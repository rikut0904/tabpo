# DB Access for macOS 仕様書

## 1. 文書概要

### 1.1 目的

macOS上で動作し、起動中のデータベースへ接続して、データベース・テーブル・データの閲覧と、セル単位の安全な編集を行えるデスクトップアプリケーションを構築する。

基本的な操作感はSequel Aceを参考にする。ただし、初期リリースではPostgreSQLを対象とし、将来MySQL、MariaDB、SQLiteなどを追加できるよう、データベース固有の処理をアプリケーション本体から分離する。

### 1.2 想定ユーザー

- 開発者
- データベース管理者
- ローカル開発環境や検証環境のデータを確認するユーザー
- SQLを使ってデータを調査・更新するユーザー

### 1.3 対象プラットフォーム

- macOS 14 Sonoma以降を初期対象とする
- Apple Siliconを第一対象とし、可能であればIntel Macにも対応する
- ネイティブmacOSアプリとして配布する

### 1.4 用語

| 用語 | 意味 |
| --- | --- |
| 接続 | DBサーバーへの接続設定と、その設定を使った実際のセッション |
| ドライバ | DB製品ごとの接続、SQL実行、メタデータ取得を担当する実装 |
| スキーマ | PostgreSQL等における論理的な名前空間 |
| セッション | アプリがDBサーバーとの間で保持する接続単位 |
| クエリタブ | SQLを入力・実行する画面上のタブ |
| 結果セット | SQL実行結果として返される列定義と行データ |

## 2. 製品方針

### 2.1 基本方針

- DB接続、データベース選択、テーブル閲覧、セル編集を1つのアプリで完結させる
- 誤操作によるデータ破壊を防ぐため、更新系操作は明示的に分かるUIにする
- 接続情報や認証情報はmacOSのKeychainを利用して安全に保管する
- DB固有の機能を共通インターフェースの背後に隠蔽する
- 大量データを一度に読み込まず、ページングと行数制限を標準とする
- UIスレッドをブロックせず、DB処理は非同期で実行する

### 2.2 初期リリースの範囲（MVP）

1. PostgreSQLへの接続
2. 接続情報の保存・編集・削除
3. データベース、スキーマ、テーブル、ビューのツリー表示
4. テーブルのカラム・インデックス・制約の確認
5. テーブルデータの閲覧、ページング、簡易検索
6. テーブルデータの閲覧、ページング、簡易検索
7. 主キーを持つテーブルのセル編集・保存
8. 接続状態、取得時間、エラー内容の表示
9. データベース切り替え
10. Light / Dark Mode対応

### 2.3 初期リリースでは対象外

- PostgreSQL以外のDBドライバ
- ER図の自動生成
- 高度なSQLフォーマッター
- SQLの自動補完における完全な構文解析
- スキーマ変更用のGUIウィザード
- リモートDBへのSSHトンネル
- 複数ユーザーによる設定同期
- クラウド上への認証情報保存

## 3. 画面仕様

### 3.1 全体レイアウト

Sequel Aceに近い3ペイン構成を基本とする。

```text
┌──────────────────────────────────────────────────────────────┐
│ ツールバー：接続 / 切断 / 更新 / 新規SQL / 設定 / 検索        │
├──────────────┬────────────────────────────┬──────────────────┤
│ 接続・DBツリー │ テーブルデータ表示・編集     │ インスペクター    │
│                │                            │ カラム・詳細情報  │
├──────────────┴────────────────────────────┴──────────────────┤
│ ステータス：接続先 / 実行状態 / 実行時間 / 件数 / エラー       │
└──────────────────────────────────────────────────────────────┘
```

- 左ペイン：保存済み接続、データベース、スキーマ、テーブル、ビュー
- 中央ペイン：SQLタブ、テーブルデータ、構造情報
- 右ペイン：選択中オブジェクトの詳細、カラム定義、インデックス、制約
- 画面幅に応じて右ペインは折りたたみ可能とする

### 3.2 接続一覧画面

表示項目：

- 接続名
- DB種別（PostgreSQL）
- ホスト名またはソケット
- ポート
- データベース名
- ユーザー名
- 最終接続日時
- 接続状態

操作：

- 新規接続
- 接続情報の編集
- 接続テスト
- 接続
- 複製
- 削除
- フォルダによる整理（MVPでは任意）

パスワードは接続設定本体と分離し、Keychainに保存する。保存しない選択肢も提供し、接続時に入力できるようにする。

### 3.3 接続設定画面

必須項目：

- 接続名
- 接続方式：TCP / Unix Domain Socket
- ホスト
- ポート（PostgreSQLの初期値は5432）
- データベース名
- ユーザー名
- パスワード

任意項目：

- SSLモード
- SSL証明書、クライアント証明書、秘密鍵
- 接続タイムアウト
- Keepalive
- 起動時に自動接続
- 接続後に選択するスキーマ

「接続テスト」は設定を保存せずに実行できる。成功時はサーバー情報とDB名を表示し、失敗時はユーザーが解決しやすいエラーへ変換する。

### 3.4 オブジェクトブラウザ

階層：

- 接続
  - データベース
    - スキーマ
      - Tables
      - Views
      - Materialized Views
      - Functions（将来）

テーブルを選択したとき、中央ペインに以下のタブを表示する。

- Data：データ閲覧・編集
- Structure：カラム、型、NULL可否、デフォルト値
- Indexes：インデックス一覧
- Constraints：主キー、外部キー、UNIQUE、CHECK
- Relations：関連テーブル（将来拡張）

### 3.5 データ閲覧画面

- 初期表示件数は100行とする
- ページングまたは追加読み込みに対応する
- ORDER BY未指定の結果に対して、並び順を保証しないことを明示する
- カラム幅の自動調整と手動調整
- NULL、空文字、バイナリ、JSON/JSONBを区別して表示する
- 長い文字列は省略表示し、セル詳細ビューで全文を確認する
- 列単位の表示・非表示を切り替えられる
- 主キーが取得できる場合に限り、行編集・削除を有効化する

更新系操作：

- セル編集
- 行追加
- 行削除
- 変更内容の一覧表示
- 保存
- 変更を破棄

保存前に変更件数と対象テーブルを表示し、削除を含む場合は確認ダイアログを表示する。初期仕様では各操作をトランザクションとして扱い、失敗時はロールバックする。

### 3.6 データベース選択

- 接続後に、接続ユーザーが利用可能なデータベース一覧を表示する
- 現在選択中のデータベースを明示する
- データベースを選択すると、そのDBへ再接続してテーブル一覧を更新する
- 接続権限のないデータベースは選択不可として表示する
- テーブル一覧はスキーマ単位で表示する

ユーザーが任意のSQLを入力・実行する画面は提供しない。アプリ内部で使用するカタログ取得、データ取得、セル更新のSQLだけをGo側で生成する。

### 3.7 SQL履歴

- 実行日時
- 接続名
- データベース名
- SQL本文
- 成否
- 実行時間

履歴はローカルに保存する。パスワード、アクセストークン、証明書情報などをSQL履歴へ保存しない。履歴の検索、再利用、削除に対応する。

### 3.8 設定画面

- 一般：テーマ、起動時動作、デフォルト行数
- SQL：タブ幅、フォント、実行確認、タイムアウト
- データ表示：NULL表示、日付表示、最大取得行数
- セキュリティ：パスワード保存、履歴保存
- 通知：長時間クエリ、接続切断、クエリ失敗

## 4. 機能要件

### 4.1 接続管理

- PostgreSQLのTCP接続に対応する
- Unix Domain Socket接続に対応する
- SSL接続に対応する
- 接続テストを実行できる
- 接続・切断・再接続を実行できる
- 接続ごとに複数のSQLタブを保持できる
- 接続が切れた場合は状態を表示し、再接続できる
- 接続ごとの設定をKeychainおよびローカル設定へ分離して保存する

### 4.2 データ閲覧・編集

- 選択したテーブルを最大100行表示する
- カラム名、NULL、日付、JSON、バイナリを区別して表示する
- 主キーを持つテーブルではセルをクリックして編集できる
- 保存時は主キーを条件にした単一行UPDATEを実行する
- 保存に失敗した場合は画面上の編集内容を保持する
- 主キーがないテーブルは閲覧専用とする
- テーブル名・カラム名は識別子として安全にエスケープする
- 行数上限とタイムアウトをGo側で強制する

### 4.3 メタデータ

共通的に以下を取得できる設計とする。

- データベース一覧
- スキーマ一覧
- テーブル一覧
- ビュー一覧
- カラム定義
- 主キー
- インデックス
- 制約

取得できない機能はエラーではなく、ドライバの対応状況として「未対応」と表示する。

### 4.4 データ型

PostgreSQLでは最低限以下を扱う。

- 数値、文字列、真偽値
- 日付、時刻、タイムスタンプ
- NULL
- JSON / JSONB
- UUID
- 配列
- BYTEA

表示用の値と編集用の値を分離する。特に日付、JSON、バイナリは、表示上の変換によって元データを破壊しないようにする。

## 5. 非機能要件

### 5.1 セキュリティ

- パスワードはKeychainへ保存し、平文ファイルには保存しない
- SQL履歴、ログ、クラッシュ情報に認証情報を出力しない
- TLS証明書の検証をデフォルトで有効にする
- 証明書検証を無効化する場合は、接続単位の明示設定と警告を必要とする
- SQL実行はユーザーが選択した接続に対してのみ行う
- 接続先、DB名、実行SQLを実行前に確認できる状態を保つ
- アプリ内ログに機密性の高いデータを保存しない

### 5.2 パフォーマンス

- 大量テーブルの一覧表示では遅延読み込みを行う
- データ閲覧の初期取得は最大100行とする
- SQL結果はUIへ一括投入せず、必要に応じて段階的に表示する
- メタデータは接続単位でキャッシュし、更新操作後に該当範囲を無効化する
- SQL実行中もUI操作、キャンセル、別タブ操作を可能にする

### 5.3 信頼性

- SQL実行エラーでアプリ全体が終了しない
- DB接続切断から復帰できる
- 変更保存に失敗した場合、未保存の変更を失わない
- アプリ終了時に実行中のSQLがある場合は警告する
- トランザクション中の切断状態を明確に表示する

### 5.4 アクセシビリティ

- macOSのキーボード操作に対応する
- VoiceOverで主要操作を利用できる
- 色だけで接続状態やエラー状態を表現しない
- フォントサイズ変更に対応する

## 6. アーキテクチャ方針

### 6.1 推奨技術構成

- アプリフレームワーク：Wails v2
- フロントエンド：React + TypeScript
- UI：HTML / CSS、必要に応じてReact向けUIコンポーネントを採用
- DB通信・ネイティブ処理：Go
- PostgreSQL接続：`database/sql`とPostgreSQLドライバ
- 認証情報：GoからmacOS Keychainへアクセスする実装
- ローカル設定：SQLiteまたはWailsのアプリデータ領域
- 配布：Wailsによる`.app`生成、DMG化、Developer ID署名、Notarization

本アプリはmacOS向けに配布するが、SwiftUIを必須としない。WailsはWeb UIを使いながら、DB接続やKeychainなどのOS依存処理をGo側へ分離できるため、画面開発の速度とネイティブアプリとしての配布を両立しやすい。

利用するライブラリは、接続キャンセル、TLS、PostgreSQL型、ライセンス、macOS対応状況、Apple Silicon対応状況を確認して選定する。

#### 技術選定の理由

- React / TypeScriptにより、テーブル、SQLエディタ、ツリー、タブなどのUIを実装しやすい
- Go側にDB処理を集約することで、DB接続情報やSQL実行をフロントエンドから直接扱わない構成にできる
- WailsはWeb UIとGoバックエンドを単一アプリにまとめ、macOS向け`.app`とDMGを構築できる
- `database/sql`のドライバ層を抽象化することで、MySQL、SQLiteなどを追加しやすい
- macOS固有機能が必要になった場合も、WailsのGo実装または小さなネイティブモジュールで補完できる

#### 他候補との比較

| 技術 | 評価 |
| --- | --- |
| Wails v2 + React + Go | 第一候補。GoによるDB実装、Web UI、DMG配布に向く |
| Tauri 2 + React + Rust | 軽量だが、Rustの学習・実装コストを考慮する必要がある |
| Electron + React + Node.js | 実装しやすいが、アプリ容量とメモリ使用量が大きくなりやすい |
| .NET MAUI | C#資産がある場合は候補だが、macOS向けDBクライアントとしてはTauriより選択理由が弱い |
| SwiftUI + Swift | macOSネイティブ性は最も高いが、今回はWeb UI技術を優先するため採用しない |

#### Wailsでの責務分離

```text
React / TypeScript
  └─ UI、画面状態、入力、表示、ユーザー操作
       │ Wails Bindings / Events
 Go Core
  └─ 接続管理、SQL実行、トランザクション、Keychain、ファイル出力
       └─ Database Driver Protocol
            ├─ PostgreSQL Driver（初期実装）
            ├─ MySQL Driver（将来）
            └─ SQLite Driver（将来）
```

フロントエンドへは、パスワードなどの秘密情報を必要以上に返さない。SQL実行や接続操作はWailsのBinding経由で行い、Go側で入力検証、接続先管理、エラー変換を実施する。

#### `database/sql`の利用方針

ユーザーが接続する外部DBへのアクセスは、GORMなどのORMではなく`database/sql`を基本とする。理由は、任意のテーブル・カラム・SQLを動的に扱い、結果セットの列構成を事前に固定できないためである。

- PostgreSQL：PostgreSQL対応ドライバを`database/sql`の実装として利用する
- SQL実行：`QueryContext`、`ExecContext`を使用し、タイムアウトとキャンセルをContextで伝播する
- 結果表示：`Rows.Columns`と`Rows.Scan`を利用し、動的な列構成に対応する
- トランザクション：`sql.Tx`を利用する
- 接続管理：`sql.DB`の接続プール設定を接続プロファイルごとに管理する
- DB固有処理：システムカタログSQL、型変換、エラー変換をドライバ実装へ閉じ込める

GORMはアプリ内の固定モデルが必要になった場合に限り、ローカル設定ストアなどで採用を検討する。ユーザーの外部DBに対する標準アクセス層では使用しない。

### 6.2 レイヤー構成

```text
UI Layer
  └─ ViewModel / Application State
       └─ Database Service
            └─ Database Driver Protocol
                 ├─ PostgreSQL Driver（初期実装）
                 ├─ MySQL Driver（将来）
                 ├─ SQLite Driver（将来）
                 └─ その他のDriver（将来）
```

UIはPostgreSQL固有のクラスを直接参照しない。DB種別をまたいで共通化できる操作はプロトコルで表現し、DB固有の拡張はCapabilityとして公開する。

### 6.3 ドライバ抽象化

概念的なインターフェース（Goのinterfaceを想定）：

```go
type DatabaseDriver interface {
    Kind() DatabaseKind

    Connect(ctx context.Context, configuration ConnectionConfiguration) (DatabaseSession, error)
    Disconnect(ctx context.Context) error
    TestConnection(ctx context.Context, configuration ConnectionConfiguration) (ConnectionInfo, error)
    Execute(ctx context.Context, request QueryRequest) (QueryResult, error)
    Cancel(ctx context.Context, queryID QueryID) error
    LoadCatalog(ctx context.Context) (DatabaseCatalog, error)
}
```

共通モデルとして、`ConnectionConfiguration`、`DatabaseCatalog`、`TableDefinition`、`ColumnDefinition`、`QueryRequest`、`QueryResult`、`DatabaseError`を定義する。

ドライバが持つべき責務：

- 接続と切断
- 認証とTLS
- SQL実行とキャンセル
- DB固有のエラー変換
- メタデータ取得
- DB固有データ型の表示・編集変換
- トランザクション制御

UIや共通サービスが持つべきでない責務：

- PostgreSQLのシステムカタログSQL
- PostgreSQL専用の型判定
- ドライバ内部の接続オブジェクト

### 6.4 Capability設計

DBごとに対応範囲が異なるため、以下のような能力を問い合わせ可能にする。

- `supportsTransactions`
- `supportsQueryCancellation`
- `supportsTableEditing`
- `supportsViews`
- `supportsIndexes`
- `supportsSSHTransport`
- `supportsExplain`
- `supportsGeneratedColumns`

未対応機能はUIから非表示または無効化し、理由を確認できるようにする。

## 8. エラー・確認仕様

エラーは少なくとも以下に分類する。

- 接続設定エラー
- 認証エラー
- TLS / 証明書エラー
- ネットワークエラー
- SQL構文エラー
- 権限エラー
- タイムアウト
- キャンセル
- データ変換エラー
- トランザクションエラー
- 未対応機能

画面上では、概要、DBからの原文メッセージ、可能な対処、詳細情報を分けて表示する。機密情報を含む可能性があるため、エラー全文を自動で外部送信しない。

以下の操作では確認を要求する。

- 行削除
- 複数行削除
- `DELETE`、`TRUNCATE`、`DROP`、`ALTER`などの危険なSQL
- 未保存変更を破棄
- 接続プロファイル削除
- 実行中SQLを停止

## 10. ログ・診断

- 通常ログは最小限とし、SQL本文や結果データは記録しない
- 開発者向けに診断ログの有効化を提供する
- 診断ログでは接続先のパスワード、SQL内のリテラル値、結果データをマスキングする
- 「診断情報をコピー」では、OS、アプリバージョン、DB種別、ドライババージョン、エラー分類を出力する
- ログ保存期間と削除方法を設定画面から確認できるようにする

## 11. テスト方針

### 11.1 ユニットテスト

- 接続設定の検証
- Keychain保存・取得の変換処理
- SQL履歴の機密情報マスキング
- DBエラーの分類・表示文言変換

## 13. 受け入れ条件（MVP）

- PostgreSQLへTCPまたはUnix Domain Socketで接続できる
- 接続情報を保存し、次回起動時に再利用できる
- パスワードが平文ファイルに保存されない
- データベース、スキーマ、テーブルをツリーから確認できる
- テーブルの構造とデータを確認できる
- 100行単位でページングし、取得上限を超えて無制限に読み込まない
- SQLを実行し、成功結果とエラーを確認できる
- 実行中のSQLをキャンセルできる、または未対応であることを明示する
- CSVとして結果をエクスポートできる
- SQL履歴を確認・再実行できる
- 接続失敗、権限エラー、SQLエラー、タイムアウトを区別して表示できる
- DBドライバを追加する際に、UIのPostgreSQL依存コードを変更せずに済む構成になっている

## 15. 初期実装時の判断

初期実装では、PostgreSQL固有の機能を無理に共通化しない。共通化できる接続・クエリ・カタログ・結果セットの契約を先に定義し、PostgreSQLの型やシステムカタログなどの固有部分はドライバ内部へ閉じ込める。

特に、SQLの完全な方言共通化は行わない。SQL本文はユーザーが選択したDBへそのまま送信し、アプリが提供するのは接続・実行・表示・安全確認の共通機能とする。
